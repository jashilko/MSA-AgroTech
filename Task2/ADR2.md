## Описание основного решения: 
1. **Используем архитектуру Edge-first**. На каждой ферме размещаютс компоненты информационной системы обеспечивающие ее автономную работоспособность: сбор данных, обработку событий, уведомление сотрудников фермы, бизнес-правила для принятия решений по инфраструктуре и действиям с животными. Это позволит ферме автономно фуннкционировать при отсутствии интернета.
2. **Видеоаналитику размещаем в контуре фермы**. Нейросетевая модель партнеров получает данные с камер наблюдения по RTSP, анализирует и представляет вероятности событий. Размещение видеоаналитики на ферме так же позволяет избежать недоступности при отсутствии интернета.
3. **Для интеграции с оборудованием используем шлюз IoT Gateway** на Node-RED. Обмен телеметрией и командами происходит по протоколу MQTT. Шлюз обеспечивает адаптацию протоколов различных производителей и отправку данных в Кафку
4. **Для асинхронного обмена событиями на ферме используем Кафку**. Брокер позволяет добавлять новых потребителей независимо. Сервисы контроля инфраструктуры и животных получают данные из кафки
5. **Прикладные сервисы (управления животными и инфраструктурой) написаны на java**. Данные хранятся локально на ферме в PostgreSQL. 
6. **Команды на отправку оповещений реальзованы через REST**. Сервис оповещений отправляет уведомления в локальный Web-портал, а в случае его недоступности, отправляет команду в SMS-шлюз для оповещения по средствам СМС.
7. **Локальный Web-портал** созданн для независимости фермы от внешней сети. Написал на React + FastAPI. Идентификация в нем происходит по локальному кэшу.
8. **Для синхронизации между фермами и офисом используется локальный Sync Agent и центральный Ingestion Server**. Sync Agent получает данные из PostrgeSQL и передает их через REST в  Ingestion Server. Центральный сервер принимает данные с ферм и передает их в хранилище. В обратном направлении передаются данные необходимые для авторизации и аналитика по прогнозам запаса кормов. 
9. **Аналитика построена на базе уже существующей архитектуры** Центрального офиса. Используется DWH, аналитический модуль и BI-система. Доработка необходима для создания модели расчета запасов еды на ферме. Так же аналитик может строить новые отчеты имея в центральном хранилище DHW данные с ферм.

## Описание альтернативного решения: 
1. **Используем гибридную архитектуру**. На фермах остаются только критически важные элементы инфраструктуры по получению данных с датчиков и синхронизации с центральным офисом.
2. **Видеоаналитику выносим в центральный офис**. Это позволяет сократить расходы на содержание серверов на каждой их ферм и количестве лицензий на модель. Но требует доп расходов на резервный канал связи. 
3. **Для интеграции с оборудованием используем шлюз IoT Gateway** на Node-RED. Обмен телеметрией и командами происходит по протоколу MQTT. Шлюз обеспечивает адаптацию протоколов различных производителей и отправку в модуль синнхронизации с центральным офисом. 
4. **Для обмена сообщениями в центральном офисе между новыми сервисами переиспользуем существующий брокер Kafka**. Это даст экономию на железе и переиспользование текущих практик 
5. **Прикладные сервисы (управление животными и инфраструктурой) размещены в контуре центрального офиса**. Это позволяет оптимизировать их обновление и расходы на поддержание железа и его резервирования на каждой из ферм.
6. **Сервис оповещений размещен в центральном офисе**. Он отправляет команду оповестить на Web-портал и дублирует оповещение в смс.
7. **Единый Web-портал в центральном офисе** обеспечивает единую авторизацию и аутентификацию пользователей. Упрощается его сопровождение.
8. **Для синхронизации на фермах используется Farm Edge Agent, а на стороне центрального офиса - Farm Integration Service**. Взаимодействия с происходит через REST. Для буферизации данных в случае проблем с соединением на фермах используется БД на PostgreSQL или SQLite
9. **Аналитика построена на базе уже существующей архитектуры** Центрального офиса. Используется DWH, аналитический модуль и BI-система. Доработка необходима для создания модели расчета запасов еды на ферме. Так же аналитик может строить новые отчеты имея в центральном хранилище DHW данные с ферм.
